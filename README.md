# 织物猪设计test

> 当前为本地待发布版本。下方 GitHub 安装地址在仓库与 v1.0.0 发布完成后才可使用；本地可先执行 `npm ci` 和 `npm start`。

本地运行的服装设计工作台，支持模特上身图、单品展示图、尺寸标注图、成图微调和历史方案管理。

**安装与 API 配置分开：先安装打开工具，随后配置自己的 API 才能整理提示词和真实生图。安装包不包含任何私人密钥、历史方案或用户上传素材。**

## 运行条件

- macOS、Windows 或 Linux，安装 [Node.js](https://nodejs.org/) **24.5 或更新版本**，包含 npm / npx。
- 安装时需要能访问 GitHub 与 npm；生图时需要能访问对应模型服务。
- 本应用只监听本机 `127.0.0.1`，不作为公开托管服务。

## 第一步：一条命令安装并打开

在终端执行（Windows 使用 PowerShell；如系统阻止 npx.ps1，可将 npx 换成 npx.cmd）：

```sh
npx --yes https://github.com/kesavx/zhiwuzhu-design-test/releases/download/v1.0.0/zhiwuzhu-design-test-1.0.0.tgz
```

首次自动下载工具及依赖，随后打开本地网页。终端保持运行，按 `Ctrl+C` 停止。以后也使用这条命令启动。

默认地址是 `http://127.0.0.1:8787`；若端口被其他工具占用，会自动选择下一个空闲端口，请以终端输出为准。

**此时没有 API 配置，界面可以打开，但不能优化提示词或真实生图。不会用演示图片冒充生成结果。**

## 第二步：一条命令配置 API

另开一个终端执行：

```sh
npx --yes https://github.com/kesavx/zhiwuzhu-design-test/releases/download/v1.0.0/zhiwuzhu-design-test-1.0.0.tgz configure --provider openai
```

按提示粘贴自己的 API Key 并回车。输入不会显示，也不会将密钥写入这条命令的历史记录。配置成功后刷新已经打开的工作台即可。

使用豆包／火山方舟时：

```sh
npx --yes https://github.com/kesavx/zhiwuzhu-design-test/releases/download/v1.0.0/zhiwuzhu-design-test-1.0.0.tgz configure --provider ark
```

默认模型沿用工作台版本配置，**你的账号需要有对应模型的访问权限和可用额度**。如果默认模型不可用，可在上述配置命令后加上 `--understand-model 你的理解模型ID --image-model 你的生图模型ID`，或在「管理后台 → 模型连接设置」中修改。仅保存密钥不会发起付费测试；实际生成按服务商计费。

两家服务的密钥分开保存，重新执行命令可以切换当前服务。也可通过 `--key-stdin` 从标准输入读取密钥，供自动化部署使用；不要把密钥直接作为命令参数。

## 内置功能

- 模特上身图：根据分部位素材整理要求，再审阅提示词并生图。
- 单品展示图：上衣、裤子、连衣裙分别使用内置拼接图模板；连衣裙为竖向正背面和细节拼图。
- 尺寸标注图：使用人工填写尺寸，支持程序标注编辑。
- 成图微调：保留原图并建立新的历史版本。
- 历史方案：多选、筛选全选、删除所选；删除方案会同时移除其历史版本。当前采用持久删除标记，底层图片保留以避免破坏共享引用，删除不释放磁盘空间。
- 管理后台：六份提示词编辑、三张单品模板预览、模型配置。

## 数据与隐私

数据默认保存在用户主目录的 `.zhiwuzhu-design-test` 文件夹。模型配置、上传素材、生成结果与历史记录都在这里，不放在 npm 缓存中。更新工具不会自动清空这个目录。

- API Key 保存在本机配置文件，不打包到 GitHub，也不回显到网页接口。macOS/Linux 配置文件使用仅当前用户可读写权限；这不是加密保险箱。
- 优化提示词与生图会把本次要求和参考图片发给所选模型服务，请使用有权处理的素材。
- 内置模板只参考布局与摄影效果，不应替代本次确认款式。
- 背面或不清晰细节可能按同款风格推定，结果需要设计师审阅，不等同于生产工艺单。
- 模型审核失败不会自动重试付费请求。

需要自定义数据目录时，在启动和配置命令末尾都传入同一个 `--data-dir 路径`。也可以设置环境变量 `FABRIC_PIG_DATA_DIR`。

## 常见问题

- **没有 Node.js**：先安装 Node.js 24.5+，然后重新打开终端。
- **网络连接失败**：检查 GitHub、npm 和模型服务的网络连通性。启动命令支持继承 `HTTPS_PROXY` / `HTTP_PROXY`，不内置某台电脑的代理地址。
- **API 配置成功但无法生图**：检查账号额度、模型权限、填写的模型 ID 与输入内容。配置保存成功不代表服务商已验证密钥或开通模型。
- **不自动打开浏览器**：复制终端打印的本机地址，或添加 `--no-open` 手动打开。
- **数据备份**：先停止工具，再复制完整 `.zhiwuzhu-design-test` 目录；其中包含 API 密钥，不要公开分享。

## 从源码运行

```sh
npm ci
npm start
```

运行自动化测试：

```sh
npm test
```

以上测试使用临时数据和模拟模型，不会调用付费生图。代码中的 `app/` 是工作台，`bin/cli.cjs` 是安装后启动与配置入口。
